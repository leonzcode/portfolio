# CLAUDE.md — portfolio

Operational guide for working inside this repo.

> **Path conventions in this doc:** bare paths like `src/pages/index.astro` are relative to this repo root — run commands from the repo root unless noted. Paths starting `D:\code\personal\...` refer to **workspace-only files** that don't live in this repo (cross-repo overview docs, scratch scripts, source images). Those exist only on the author's local machine.

Strategic context (why this exists, how it fits with `mlhub/`) lives in `D:\code\personal\deployment.md` (workspace-only — not in this repo). Full deploy procedures (Cloudflare Pages via GitHub Actions, lessons learned) live in `DEPLOYMENT.md` (same directory as this file).

## What this repo is
Leon Zhao's portfolio site at `leonzhao.dev` (apex). Static Astro 5 + Tailwind 4 site deployed to Cloudflare Pages on push to `main`. Audience: college admissions officers — every design and content decision should serve that audience.

## Design decisions (locked 2026-05-25)
- **Visual reference**: `https://gungho0619.vercel.app/` — clean, sans-serif, left-aligned, project-card grid. Match restraint, not maximalism.
- **Framework**: Astro 5 + Tailwind CSS 4 (via `@tailwindcss/vite`).
- **Theme**: Default **light**, switchable to dark via toggle at top-right of every page. Pre-paint inline script in `BaseLayout` prevents flash.
- **Tab order**: About → AI → Science → Math → Film → Games → Contact. Seven items (reordered by Leon 2026-06-11, same day **Physics was renamed Science** with route `/physics` → `/science` + 301s in `public/_redirects`; Film added and Games moved to the end June 2026). Originally six (About → AI → Games → Math → Physics → Contact).
- **Per-tab pages**: each category gets its own page. Landing = About summary. **Film** (`film.astro`, Leon June 2026) is a YouTube video gallery, not a project-card grid — its video list (id + title + description) is inline in `film.astro`, NOT in `projects.ts`.
- **Views, likes and comments on every project** (Leon, 2026-10-02; this replaces the original "no comments / no public threads" decision). Each project detail page has `ProjectSocial.astro` under its title: a view count (once a day a visitor), a like button, and a Comments button that opens a thread with replies and likes on comments. Cards show "N views · N likes". All of it lives on mlhub (`apps/mc/sitesocial.js`, `/mc/site/*`): names and text go through the game chat filter, there are length and rate limits, and an admin deletes a comment by opening a project page with `#admin` once (the kart admin code is kept in localStorage and checked on the server). A visitor is a random browser id, not a login.
- **About voice**: first-person ("I build..."). **Privacy filter**: no school name, no city, no SAT score, no "Top 10%", no email on About, no resume PDF link, no job-seeking language. Public site shows: name, grade, achievements/programs, snowboarding hook. `Golden Gate STEM Fair` is allowed despite mild Bay Area location leak — award is meaningful enough to keep.
- **Site mark**: `public/logo.png` (mascot, not a portrait). Used in `Header.astro`.
- **Project counts**: 5 AI, 18 Games (`castlefall` added 2026-07-29, `leon-kart` 2026-09-20), 5 Math, 4 Science (`ski-resort` trail-map added first 2026-06-11, + doppler/circuit/kinetic-theory), plus the Film video gallery. AI projects: `avalanche`, `ai-art`, `litterbot`, `aihiring`, `wordle`. (`chatgpt` removed 2026-05-28; `docs` removed June 2026; `litterbot` added June 2026.) Tabs are content-complete (no placeholders).
- **GitHub handle is `leonzcode`** (Leon rebranded from `leoniscooler`, June 2026). The Games/Math/Science external demo URLs are `https://leonzcode.github.io/<slug>/` (except `ski-resort`, which is local-only at `/legacy/skiresort.html`); the old `leoniscooler.github.io` URLs now 404. Footer GitHub icon links to `github.com/leonzcode`.
- **Detail pages for ALL categories + iframe embedding** (Leon 2026-05-28, supersedes the original AI-only decision below): every project across AI/Games/Math/Science has a detail page (`/<category>/[slug].astro`). Cards link internally to it; the detail page **embeds the playable app/program in an `<iframe>`** so visitors can use it inline, plus an **"Open full screen"** button (same-tab) for standalone view. (Renamed from "Open full app" 2026-06-08 — clearer for the admissions audience: it says the button escapes the small embedded frame.)
  - The iframe source is `playableHref = project.localHref ?? project.href`.
  - **Per-project GitHub repo link (AI ML apps, added 2026-06-08):** projects with a `repo` field in `projects.ts` render a secondary **"View code ↗"** button (outline, new-tab) next to the demo button, plus a closing line "The source code, training notes, and model files are available in the GitHub repo." Both link `project.repo`. Set only for the 3 published public repos — `avalanche` → `leonzcode/avalanche-risk-forecasting`, `ai-art` → `leonzcode/ai-art-detector`, `litterbot` → `leonzcode/litterbot-ai`. `aihiring`/`wordle` have no public repo, so they get no repo button or closing line (graceful). These public repos are the AO-facing source of truth (clean READMEs, scrubbed training notebooks, models, MIT/AGPL licenses).
  - **AI apps**: `avalanche`, `ai-art`, `litterbot` iframe the Hetzner Streamlit apps at `apps.leonzhao.dev/<app>/`. `aihiring` and `wordle` are now **self-hosted as static files on Cloudflare** under `public/apps/<slug>/`, served at `leonzhao.dev/apps/<slug>/` — these are also iframed (their URLs end in `leonzhao.dev`). So as of June 2026 **all 5 AI projects are embedded**; none open in a new tab anymore. (`docs` and `chatgpt`, the old github.io off-domain ones, were removed.)
  - **Games/Math/Science**: iframe points at the self-hosted local copy `/legacy/*.html`. The `localProjectPaths` map at the bottom of `projects.ts` assigns each slug its `localHref`. (`ski-resort` skips the map: it has no external URL, so its `href` IS the local path.)
  - **Iframe vs new-tab rule**: a destination whose hostname ends in `leonzhao.dev` is iframed (we control it / it has a way back); anything off-domain opens in a new tab. With aihiring+wordle moved onto `leonzhao.dev/apps/`, there are currently no off-domain AI demos left.
- **Original AI-only detail-page decision (2026-05-25, now superseded)**: kept for history — the initial design gave detail pages only to AI projects (story + screenshots + "Launch demo"), with Games/Math/Physics linking straight out, because there were "too many" of the latter for detail pages. Leon replaced this on 2026-05-28 with the embed-everything approach above.
- **Show-more pattern** on every project list page: first 2 cards shown by default, "View all N" black-pill button reveals the rest, "Show less" collapses. Pages with ≤2 projects skip the button. Implemented as reusable `<ProjectGrid>`.
- **Grid: always 3-col** (`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`). No state-based column switching — uniform card rhythm matches science/research-portfolio convention. Considered (and rejected 2026-05-25) a 2-col-collapsed → 3-col-expanded switch; the resize-on-click read as a layout shift.
- **Width strategy**: About + Contact use `max-w-3xl` (~768px, optimal reading line length). AI/Games/Math/Science + AI detail pages use `max-w-6xl` (~1152px) for browsing. Toggled via the `wide` prop on `BaseLayout`.
- **Typography baseline** (legibility-tuned for admissions audience): body 16px, page h1 32–36px responsive, section h2 18px, nav 14px, card title 16px, card description 14.5px, button label 14px. Geist Sans + Geist Mono via Google Fonts.
- **AI card images** live in `public/cards/`. Each AI project's `image` field in `src/data/projects.ts` references `/cards/...`. The detail-page template falls back to this image as its hero when no `screenshots[]` array is provided — so one PNG serves both the card thumbnail and the detail-page hero.

## Leon Kart: profiles, cosmetics, built maps (2026-10-02)
- **The name is the account.** `mlhub/apps/mc/kartprofile.js` keeps, per lowercased name: the look (driver, character colours, paint and gradient, cosmetics worn), the inventory won, stats from every run (`POST /mc/kart/run`), and recent grants. `GET/POST /mc/kart/profile`.
- **Cosmetics are won, never bought**, and the tier follows the win: multiplayer race win = common, a new best place in a track's time trial top ten = rare, ranked win = epic, #1 on a track or every third ranked win = legendary. The catalogue is in `public/mario/cosmetics.js` and must match the server's `ITEMS` list. Paint skins and gradients are a shader on the paint (no UVs needed); themed bodies, hats, gliders, decorations and Thomas's sunglasses are geometry in `cosmetics-art.js`. Brayden plates are an inventory item now, not a default.
- **Thomas** is the ninth driver. `packLook` keeps racers 0-7 exactly as before and puts racers past the eighth above the paint.
- **Character colours** (skin, shirt, trousers) are vertex colours with roles worked out from the Kenney texture at load (`drivers.js colourRoles`); `tintDriver` makes a recoloured copy per look.
- **Home screen**: three play buttons, then one row of pages (`hub.js`): Inventory, Stats, Custom maps, Requests. The garage card has Kart / Paint / Driver tabs.
- **Built maps** (`editor.js`, objects in `mapobjects.js`): fly-and-place builder, Y to drive / build, P for the list picture. Maps are built by the normal track generator from the builder's points (`setCustomTrack` in track.js). Stored by `mlhub/apps/mc/kartmaps.js`: password to edit (an admin needs none and can change the list's settings), likes/dislikes, a board per map. Custom map times never go on the circuits' boards.
- **Performance setting** (Settings → Performance; `public/mario/perf.js`, kept in localStorage `mk_perf`): Full / Balanced / Light / Minimal set a share of each kind of decoration (catch fence, scrub, boards, floodlights, flags, crowd, the far woods and skyline...). Applied at once: track-builder scenery is trimmed through `InstancedMesh.count` (`applyToTrack`), props are rebuilt. Barriers, cones, hazards, ice, lava, boulders and item boxes are never touched, so a lobby races the same circuit at any level. A kind at 0 is never built, so its model is never downloaded.
- **Physics stays in the browser.** Measured 26-40 ms round trip (median 36) to the server from the Bay Area; server-side physics would add that to every input, which fails Leon's "only if it does not increase lag" condition.

## Leoncraft 2 at `/leoncraft2` (2026-10-03)
A separate single-player engine (not built on `legacy/minecraft.html`), for "realistic shader" graphics and Minecraft 1.18+ style terrain. Not linked from the nav; the page has `noindex`. Round 2 (2026-10-03, later the same day) added every block up to 26.3, menus, an inventory, a visible player and saving.
- **Layout**: `public/leoncraft2/index.html` loads Three from `/legacy/vendor/` then `js/main.js` (boot, title world, game loop, input). `js/`: `blocks.js` (the block table: hand-made blocks first, then everything in the generated `blockdata.js`), `models.js` (box shapes: slabs, stairs, fences, doors... and their collision/selection boxes), `place.js` (placement states, doors/gates opening, what breaks with a block), `interact.js` (mining over time, held-button repeat), `survival.js` (health, air, fall damage, break times, drops), `save.js` (edits per chunk in IndexedDB, player state in localStorage), `worldgen.js` + `noise.js` + `biomes.js`, `mesher.js`, `worker.js`, `world.js`, `fluids.js`, `player.js` (movement with box collision and 0.6 step-up). `js/render/`: `renderer.js`, `avatar.js` (the player model, skin, animations, Q/F5 views, first-person arm), `blockmesh.js` (one block as a mesh, for the hand), `overlay.js` (selection outline, breaking cracks), `sky.js`, `ldrsky.js`, `materials.js`, `water.js`, `post.js`, `interaction.js`, `noisetex.js`, `glsl.js`. `js/ui/`: `gui.js` (one 2D canvas at the classic integer GUI scale, widgets, `Options`), `font.js`, `menus.js` (title, worlds, create world, options pages, pause, loading, death), `inventory.js`, `icons.js`, `hud.js`.
- **No Mojang files.** Programmer Art (and "Programmer Art Fix") is Mojang's or all-rights-reserved, so it is not used. Block textures are Pixel Perfection CE plus Pixel Perfection Legacy for 1.17+ blocks (both CC BY-SA 4.0); GUI sheets are Pixel Perfection CE with our own grey buttons/hotbar (`tools/leoncraft2/build_gui.py`); the skin is original. Credits in `textures/LICENSE.txt` and the in-game Credits screen must stay. **The packs are not clean**: a pixel audit against Mojang's jars (2026-10-03) found copied or traced Mojang textures in both (portal, tripwire, jigsaw/structure blocks, wither rose, conduit, some glazed terracottas, the end portal entity art, the grass colour map...). `build_textures.py` keeps them out (`NOT_FROM_CE`, `NOT_FROM_PPL`, `REPLACE`, our own art in `tools/leoncraft2/art/`); never take entity, GUI title/presets, sound or item files from a pack without checking them the same way.
- **Rebuilding data**: `python tools/leoncraft2/build_blocks.py` (writes `js/blockdata.js` from `tools/leoncraft2/data/`, MIT minecraft-data derived), then `python tools/leoncraft2/build_textures.py <PixelPerfectionCE-master> <PPL root>`, then `python tools/leoncraft2/build_gui.py`. The texture strip is about 1400 layers; `main.js` uploads it in 128-layer pieces because many GPUs refuse one 22 000-pixel upload.
- **Every import, the worker and the textures carry `?v=N`** (Pages ignores Cache-Control). Bump all of them together after a change (every `?v=` in `js/**` and `index.html`, the `TEX_V` constant and the Gui `version`).
- **Worldgen** follows the game's biome slice tables and is calibrated to its height statistics (median 63, peaks to about 240); seeds do not match real Minecraft (different noise permutation).
- **Testing**: headless swiftshader runs about 1 fps; real-GPU timings work headless with `--use-angle=d3d11 --enable-gpu`. Drive things through `window.__lc2` (`play(seed, mode)` starts a test world without the menus; `world`, `player`, `inv`, `renderer`, `gui`). URL options: `?q=detailed|fast`, `?seed=`, `?at=x,z`, `?rd=`, `?scale=`.
- **Video Settings is the game's own (26.x), with one Shaders button** (2026-10-06, the button 2026-10-07): `js/ui/video.js` has Video Settings with vanilla's three sections (Display, Quality & Performance, Preferences), the same buttons, order, labels, values and tooltips (from the 26.1.2 lang file), the Preset slider (Fast / Fancy / Fabulous!, the wiki's table in `PRESET_VALUES`, Custom when one is changed by hand); View Bobbing, FOV Effects, Glint Speed/Strength and Damage Tilt are in Accessibility, as in the game. The only thing the game does not have is the footer's **Shaders** cycle button beside Done (Leon: "one button for shaders"): **Off / Low / Medium / High / RIP Computer**, option `shaderLevel`, **Off by default**. There are no Shader Packs or Shader Options screens any more. Old settings: `Options.carryShaders` turns a never-chosen shader setting (the old default, on) into Off, and an explicit Shaders ON into Low / Medium (light presets) or High (Ultra or a full-chain custom); the render resolution goes back to Auto. `?q=off|low|medium|high|rip` (and `fast` / `detailed`) picks a level for one visit. Under a menu the HUD is blurred with the world, as the game does. **Off is the game with no shaders** (Leon, 2026-10-04: "just no shaders and normal minecraft"): `js/render/vanilla.js` draws it as Minecraft does (face shades 1.0/0.8/0.6/0.5, smooth-lighting corner shade 0.4 + 0.2 per open side, the 16x16 lightmap rebuilt each frame from the game's formula, smoothstep cylinder fog, sky plane + sunrise fan + square sun/moon + stars, 12x4x12 clouds at 192, water as the texture's grain in the biome colour). The levels are settings objects in `render/looks.js` (`SHADER_DEFAULTS` + `LEVEL_SETTINGS`): **Low** and **Medium** are the light pipeline (lit per vertex, one pass to the screen; Low has hard 1024 shadows to 48 blocks, still water and leaves; Medium is the old default look with soft 2048 shadows to 64); **High** and **RIP Computer** are the full chain (`render/post.js`, per pixel: bloom, light shafts, volumetric clouds and their shadows, SSR water, normal maps, the look from before the shaders were lightened; High: 3072 shadows to 96 blocks, 8 soft taps; RIP: 4096 to 128, 16 taps, light shafts 32 steps, clouds 32 steps, reflections 48 steps, strong bloom). **Shadows** (`render/shadows.js`, rewritten 2026-10-07 for "the shadows are very weird and jump around"): an even orthographic grid (no squeeze towards the player), its rows along the sun path's own axis (`x cross light`), its centre snapped to whole texels, reaching a margin of D/8 past the shadow distance and only moved once you walk into it, so a redraw for a new place puts every texel where it was; redrawn as soon as a shadow eight blocks long would creep 1/32 of a block (`sin(elevation)^2 / 256` radians: every few seconds at noon, without a break at sunrise and sunset), when blocks near you change, or for a new centre; drawn over `shadowSlices` frames into the back map from **its own view** (`uShadowDraw`; the shadow pass used to read the front map's `uShadowMat`, so every new map came out shifted by however far the map had moved, which was the jumping), then swapped. The fade to the light level's guess and the soft/hard switch go by distance from you (`uShadowEye`), never from the map's middle. **Lava** looks like the game's in every level: the shader path samples it as `vanilla.js FLUID_FS` does (still on top, flow texture turned downhill and down the sides, frames from the layer table: it used to assume 20 frames, and lava_still has 16, so it showed light grey terracotta, lilac and lily of the valley a fifth of the time), with the game's face shade, at full light; Low/Medium put it straight on the screen with the fog laid over in screen colours, High/RIP work it back through the eye and AgX (`glsl.js agxInverse`) and mark it (alpha 2) so the eye's measure leaves it out (`post.js FS_LUM`; otherwise a lava sea would drag the exposure down without end). **Everything applies while you play, with no reload**: `js/settings.js` hears each option; `render/looks.js applyLook` keeps every material object and gives it the new shader code (`morph`), compiling the new programs in the background first (handed over one at a time, two on eight threads or more (`COMPILE_AT_ONCE`), the next only when one is built: all at once they took every core the first time and the game stopped for 0.3 to 2.6 s; each one's uniforms fetched as soon as it is built, so the frame the look lands in asks the graphics process nothing); modules that make their own materials pass a maker to `renderer.looked(o => material)`. **Keep ANGLE/D3D11 from building shaders at draw time** (2026-10-06; that was the hang after a change of look, a third of a second or more a shader): the terrain vertex format is read as integers (`in uvec4 aPos;` + `#define aPos vec4(aPos)` in every shader of that format, `gl.vertexAttribIPointer` for the chunk VAOs, `intAttribute()` from blockmesh.js for three.js geometry in it); a float input fed non-normalised integers makes ANGLE compile a new vertex shader at the first draw. Flat varyings use the first corner (`WEBGL_provoking_vertex`, looks.js), or ANGLE adds a geometry shader to every such program, built on the GPU process's main thread at its first draw (a trace of the first Ultra: 14 of them, 111 ms, with the last corner; none with the first). **Nothing on the page's thread may wait while a look changes**: no `new Worker` while the cores are flooded (starting one held the page up a third of a second to a second when every program was compiling at once; the volumetric clouds' 3D noise is drawn by the graphics card, `noisetex.js makeNoise3DGPU`; the normal maps' worker starts in 0.1 ms now), no `gl.getParameter` or other query that waits for the graphics process (`r.capabilities` keeps the answers), no table rebuilt from scratch (the tone table is refilled in place, `glsl.js makeToneLut`), and a pass whose `#define`s change goes through `Post.variants()` so it is built in the background too. Normal maps are fetched when a look that wants them is asked for (`settings.js normals`), decoded and their five sizes worked out in a worker (`looks.js normalSizes`; a 2D canvas would premultiply the height in alpha away), and uploaded a whole size a frame (generateMipmap over all the layers, or a size written in pieces, made the GPU process clear and rebuild all nineteen hundred layers in one frame). A looping function called several times in one shader is unrolled that many times by the D3D compiler (the sky's light table took two thirds of a second until `sky.js FS_AMB` gathered in one loop of unknown length). A depth-only target with a colour-writing shader would need a variant too. See-Through Leaves, Smooth Lighting and Biome Blend remesh in the workers (`world.setMeshing`), keeping the old meshes until the new ones are in. Old saves: the old `quality` becomes Shaders ON/OFF and the Preset Custom (`Options.carryOver`), then a level (`Options.carryShaders`). The first time a shader level is chosen, the atmosphere's tables are drawn a part a frame and their light read back with a fence before the look lands (`looks.js firstSky`), and the light pipeline's texture table shader is built with the rest; the first switch to a level on a machine (nothing in the browser's shader cache yet) takes one to two seconds to show, the old look drawn meanwhile with no frame held up (worst frames 30 to 70 ms on the GTX 745, the same as with no switch); after that a switch lands in a fifth to a third of a second.

## The scavenger hunt at `/form` (2026-09-19)
`public/form/index.html` is a recreation of Google Forms: one form, the same one for every visitor, not linked from the nav. It is a standalone page (like `public/claire/`), not an Astro route.

- **Every form starts with the group name.** `form.nameQ` is a pinned first question: the editor can reword its title and description, and that is all. It cannot be moved, deleted, retyped or given an answer key, whatever is typed into it becomes the player's name on the standings, and it is required. The editor shows it as the first card with a grey pin bar and a fixed "Group name" chip instead of a type dropdown. The counter treats it as question 1, so a six-question hunt reads "Question 1 of 7" on the name step.
- **The answer key never reaches the browser.** A page is only sent the question it is on, stripped of its answers; the next one arrives only after the server has marked the last one right. Reading ahead in devtools gets you nothing.
- **A wrong answer starts a cooldown** before the next try. The editor sets it for the form and can override it per question.
- **Marking is forgiving by design.** Capitals never count unless the question says they do, spacing never counts at all (`ski resort` matches `SkiResort`), and a number is a number however it is written (`three`, `3`, `1,000`, `twenty one` all normalise to digits). Only `caseSensitive` is switchable; the rest is always on.
- **A Back button** walks back through the questions already got right, showing each with the answer that was given, greyed out and unanswerable. Forward returns to the live question. It can never move past what has been solved.
- **Progress survives the server losing it.** The browser keeps its own copy of every answer that was marked right, and on a page with no progress it hands that copy back; the server re-marks every answer from question one, so a hand-edited copy is worth exactly what a wrong answer is worth. The exception is deliberate: when the organiser deletes a response the uid is tombstoned in `wiped`, and the next restore from that browser is refused and tells it to forget its copy.
- **Editor**: the footer's "Editor" link (or `/form?edit=1`) asks for a password — `314159`, overridable on the VPS with `FORM_PW`. It opens a Forms-style editor: Questions, Responses and Settings tabs, six question types (short answer, paragraph, multiple choice, checkboxes, dropdown, **photo upload**), answer keys, per-question hints and cooldowns, theme colours, and the confirmation screen.
- **Several people can edit at once.** The editor does not save the whole form; it sends one op per change (`set` with a path, or `addq` / `delq` / `moveq` / `setq`), so an edit to question three never carries a stale copy of question five with it. A click goes at once, typing is debounced 500 ms per field. An incoming op patches the box it names instead of repainting, so a remote edit cannot move your cursor, and a version gap triggers a `resync`. The app bar shows how many people have the editor open.
- **Pictures**: the image button on a question card uploads a picture for that question; a **photo upload** question is answered by the hunter sending one, which counts as correct on arrival and shows up under Responses. The browser shrinks anything it sends to 1400 px and JPEG 0.85 first. Files are named by the hash of their bytes and served from `apps.leonzhao.dev/mc/form/img?id=…`, cached immutably.
- **Everyone sees everyone else's progress.** The `board` goes to every open page, so the standings sit under the question on a phone and on a computer alike: a bar graph (one bar per player, questions answered up the y axis, names along the x) and a ranked table, with your own row marked. The **QR for joining is the organiser's only** — it is rendered only into `#eboard`, so it appears on the Responses tab and the big screen but never on a player's card. The standings appear once a player has given a group name, not on the name step itself.
- **A stopwatch of their own** sits beside the form title on every player's page, running from the moment they gave a group name and stopping (and turning green) when they finish. The server sends `you.since` with each state and the page counts on between pushes; `-1` means they have not started, and the clock is not drawn.
- **Confetti on a right answer.** A canvas over the page throws paper strips up and out from the middle and lets gravity rain them down, each one spinning on its long axis (a cosine squeeze on one side is what reads as paper flipping). The last question gets a bigger burst. It respects `prefers-reduced-motion` and takes itself off the page when the last piece lands.
- The Responses tab has all of the above plus: a bar graph, a ranked table, and the QR for joining. Everyone who has given a name is on it, including players still on zero, who keep their column and their name with a `0` over the baseline. Bars are capped at 12 (7 on a phone), and the header reads "top N of M" when it cannot show everybody. The QR matrix is generated offline for the fixed URL and embedded, so the page loads no QR library; colours come from the validated eight-hue categorical set, assigned per player in first-seen order and never re-shuffled by rank (past eight, grey).
- **A clock runs beside every player** on the Responses tab, from the moment they gave their group name until the moment they finish, when it stops and turns green. It ticks locally rather than through a repaint, so the list does not rebuild itself once a second.
- **"Full screen"** on the Responses tab throws the standings up for a room: the graph takes the height, the code to join sits beside it, and the players with their counts and clocks run along the bottom. Bar width, axis type, row height, the heading and the side gutters all size themselves off the screen they are on, so a wide monitor gets a margin rather than the graph running into the bezel. Nothing scrolls. Escape closes it.
- **Deleting a response sends that player back to the group-name question.** The wipe reaches their open page, clears the copy their browser kept, and their next state push has no name and nothing solved.
- **Backend**: `mlhub/apps/mc/form.js`, reached at `wss://apps.leonzhao.dev/mc/ws?mode=form`, plus `POST /mc/form/upload` and `GET /mc/form/img`. The form and everyone's progress live in `apps/mc/data/form.json` on the VPS volume, pictures in `apps/mc/data/form_images/`, so all of it survives a redeploy. Progress is per browser (a uid in `localStorage`).
- **Mobile**: both the form and the editor are built for a phone — inputs are 16 px so iOS does not zoom on focus, the tab row scrolls, the stat tiles stay three across, and the graph is drawn at the width it actually has (it redraws on resize rather than stretching).
- Local testing: run the mc server (`PORT=8600 node server.js` in `mlhub/apps/mc`) and serve `public/` statically; the page falls back to `ws://<host>:8600/ws` off `leonzhao.dev`. `window.__form.state()` / `.editor()` expose the live state.

## Quick gotchas reference
- **PowerShell may block `npx.ps1`** by default. One-time fix: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. Microsoft's developer default; no admin rights needed.
- **Cloudflare dashboard hides Pages on new accounts**. Deep link to bypass: `https://dash.cloudflare.com/?to=/:account/pages/new/provider/github` (paste verbatim — don't replace `:account`, Cloudflare resolves it from the session).
- **Custom domains can only be removed via API**, not the dashboard. See `DEPLOYMENT.md` §Operational gotchas for the curl command.
- **Pages projects created via `wrangler pages deploy` cannot be retrofitted with Git integration**. The current setup uses GitHub Actions instead of native Git connect — see `DEPLOYMENT.md` §"Why GitHub Actions" for why.
